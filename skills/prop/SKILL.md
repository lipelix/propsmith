# Props: write, build, check, look, fix

An asset is one folder `catalog/<id>/` with two files:

- `asset.py`: a Blender `bpy` builder. Each variant is a decorated function that adds the asset's parts to the scene.
- `asset.json`: what code reads about it: search fields, size, anchors, provenance. Schema: `tools/schema.ts` (strict,
  unknown fields fail).

`npm run build -- <id>` builds it headless in Blender into `.cache/assets/<id>/`, measures it, records the measurements
in `catalog/measurements.json` (what `npm run check` checks in CI, without Blender) and prints the check report. Read
the library before writing: `lib/propsmith/` (`__init__.py` has the axes, `shapes.py`, `materials.py`). The assets
`well_stone`, `barrel_wood` and `lamp_post` are good examples.

The catalogue is engine-agnostic: no tiles, no gameplay facts, no game camera. A game adds those in its own files.

## The model contract (`asset.py`)

```python
"""A short wooden barrel with three iron hoops (generated by npm run new)."""
import math
import random

from propsmith import anchor, prop
from propsmith.materials import material, texture
from propsmith.shapes import blob, box, cylinder, torus

# Overall dimensions (metres), from the description.
R, H = 0.3, 0.9

WOOD = (0.2, 0.115, 0.058)  # linear RGB
IRON = (0.045, 0.045, 0.045)


@prop
def barrel_wood():
    rnd = random.Random(1)
    wood = material("barrel_staves", WOOD, vary=0.25, scale=14)
    ...


@prop
def barrel_wood_open():
    ...
```

- **Variants are `@prop` functions** with no arguments. The function name is the variant id: `<id>` or `<id>_<suffix>`.
  `asset.json`'s `variants` lists them in file order (the build fails otherwise). The first is the default.
- **Metres, z up.** Keep every overall dimension in named constants at the top, from real-world sizes. Never scatter
  magic numbers for overall sizes through the code.
- **Axes and origin.** The origin is the centre of the base on the ground. The model stands on z = 0: nothing floats,
  nothing sinks (the lowest point within 7 mm of 0). Local x spans `size.x`, local y `size.y`. The review camera sees
  the +x and -y faces, so put the front (door, drawer, face) on -y.
- **Stay inside `size`:** x within ±`size.x`/2, y within ±`size.y`/2 (0.075 m slack), top at or under `size.z`.
- **Shapes** from `propsmith.shapes`: `box`, `cylinder` (stands on `at`, grows up +z), `torus`, `blob` (lumpy
  icosphere, centred on `at`). Every part is its own mesh; the build joins them. Rotations are in degrees.
- **Materials** only from `propsmith.materials`: `material(name, colour, rough, vary, scale, crevice, metal)`
  (procedural, the default) or `texture(name, "<ledger id>", metres_per_repeat, tint)` for a CC0 texture of
  `catalog/textures.json`. Prefix material names with the asset (`barrel_staves`). Never make a material with
  `bpy.data.materials.new`: the `materials-known` check fails it.
- **Anchors** for effects: `anchor("light:lamp", (x, y, z))` (also `fire:`, `smoke:`, `water:`). Every anchor is
  listed in `asset.json` `anchors` and present in every variant. A fire, a `water:spout*` and a `water:basin*` need
  an extent: `anchor("fire:hearth", at, size=(half_width, half_depth, flame_height))`.
- **Deterministic.** Randomness only from `random.Random(<fixed seed>)` and the `seed` of `blob`. No time, no unseeded
  `random`, no reading files, no network. The same `asset.py` must build the same bytes.

## `asset.json`

- `name`: short English noun phrase ("Wooden barrel"). `description`: one or two sentences of what it looks like.
- `category`: one of `structure`, `door`, `fence`, `container`, `furniture`, `decor`, `vegetation`, `light`.
- `family`: what kind of thing it is across materials (`barrel`, `well`, `cart`, `pot`). Snake case.
- `tags`: only from `catalog/tags.json`, never repeating the family or an alias. Pick the material, setting, use, look
  and condition that fit; 4 to 8 tags. Do not add tags to the vocabulary yourself.
- `aliases`: other words a search should find it by ("cask", "keg").
- `size`: `x`, `y`, `z` in metres: the box every variant stays inside. Make it fit the model closely (round up to
  5 cm), not a generous guess: games read it to place the asset.
- `anchors`: the anchor names, as in `asset.py`.
- `closed`: true when every part is a closed mesh (needed to fracture or print it); the `manifold` check then holds
  you to it. Use it for things a game would break: crates, barrels, pots, furniture.
- `provenance` and `licence`: keep what `npm run new` wrote (`source: generated`, the prompt, `CC0-1.0`).

## Style (the default kit: a painterly medieval village)

- **Palette:** earthy, slightly desaturated linear RGB, values about 0.04 to 0.5 (look at the example assets' colour
  constants). Wood 0.13 to 0.25 red, stone grey-browns about 0.3, iron near 0.05, cloth and straw warmer. No pure
  white, no saturated primaries, no black.
- **Bevels on everything hard:** 0.006 to 0.025 m. Bevel highlights are what reads when the asset is small on screen.
- **Wear, not noise:** seeded jitter of a few degrees and a few percent on repeated parts (planks, stones, staves), a
  darker or older material on some of them. Nothing perfectly aligned, nothing broken unless the description says so.
- **Scale cues:** a door is 2 m high, a table top 0.75 m, a seat 0.45 m, a barrel 0.9 m, a person 1.8 m. Handles,
  hinges, hoops, rims and pegs make the size readable.
- **Silhouette first.** One strong outline with a few readable details beats many tiny parts.
- **Budget:** ≤ 8,000 triangles per variant. `blob(subdiv=1)` is about 80, `subdiv=2` about 320; a 24-segment
  cylinder about 100 before bevels. Prefer fewer segments on small parts (8 to 12).
- **Closed assets are closed meshes:** use `box`, capped `cylinder`, `torus`, `blob`; never `caps=False`, single
  planes or open shells.

## The loop

At most 5 rounds (or the number you were given). One round:

1. **Write** `asset.py` and `asset.json` with the Edit and Write tools (the first round fills every draft field).
   Under `npm run new` no script or shell command may change files.
2. **Build:** `npm run build -- <id>`, run as it is (under `npm run new` it is the one command allowed; extra options
   are `--force` and `--only <variant>`). It first rewrites `asset.json` in Prettier's layout when it is not (read it
   again before you edit it). A Python error prints Blender's traceback: fix it and build again (that counts as a
   round).
3. **Read the check report.** One line per check, each `OK`, `FAILED` or `NOT CHECKED`, and a delta line with
   triangles and the measured size in metres. Numbers come from here, never from pictures. Fix every `FAILED` line:
   - `bounds-fit`: the model sticks out of `size` or is too tall: shrink parts, or change `size` when the description
     really needs a bigger one.
   - `origin-ground`: lift or lower parts so the lowest point is at z = 0 (a `blob` is centred, a rotated box dips).
   - `tri-budget`: fewer segments, lower `subdiv`, fewer repeated parts.
   - `manifold`: replace open parts with closed ones.
   - `materials-known`: use `material()` or a ledger `texture()`.
   - `anchors-declared`: make `asset.json` and the `anchor()` calls agree; give fires and water their `size`.
4. **Look at the snapshots** in `.cache/assets/<id>/review/`: `<variant>_iso.png` (three-quarter view),
   `<variant>_top.png` (the declared size outlined) and `<variant>_front.png`. Judge only the look: does it read as
   the description, is the silhouette clear, are the colours in the palette, are there gaps, floating bits,
   z-fighting or parts poking through each other.
5. **Fix** what the report and the snapshots show, then start the next round. When the checks pass, tighten `size` to
   the measured size in the delta line (rounded up to 5 cm) and build once more.

Stop when every check is `OK` and the snapshots match the description, or when the rounds are used up. Stop early and
say so when a check needs a human: the description contradicts the budget, or it needs a texture that is not in the
ledger.

## Never

- Write outside `catalog/<id>/`, or touch other assets, the library, the review style, the ledger or the vocabulary.
- Import meshes, images or textures from anywhere; a texture comes only from a ledger entry by id.
- Import anything but `math`, `random` and `propsmith`, or use `bpy`, files, the network, `eval`, `exec` or
  `getattr` tricks: the catalogue check refuses the asset. Shapes and materials come from the library.
- Read sizes off pictures, or call an asset done with a `FAILED` or `NOT CHECKED` check.
- Edit generated files (`catalog/index.json`, `catalog/measurements.json`): `npm run build` writes them.
- Put game facts in `asset.json` (tiles, cover, hit points, interaction): the schema refuses them.

## The final report

End with a short plain report: the final delta line and check lines, two sentences on what the asset looks like, the
rounds used, and anything a human must decide.
